# macauive CLI portfolio

The main portfolio is a compact cyan lightning terminal with anonymous portfolio commands and conversational AI questions. Its full application and answer endpoint run on ChatGPT Sites. The Site identity is in `.openai/hosting.json`; reuse it on updates. The former Next.js portfolio is preserved on the GitHub branch `legacy-portfolio` at commit `60d9c13553c5ebf9e4dbdd3dbfa59f8c0b6e1d17`, including its images, source and dependency lockfile.

The existing Vercel project only forwards visitors to `https://www.macauive.dev/` using `vercel.json` and the small `vercel-public/` fallback. It does not host the Worker, serve application source, or need an OpenAI key. The temporary redirect keeps the terminal reachable while the apex domain's DNS moves to Sites; it can remain as a fallback for the old Vercel address.

To work on the old design independently, fetch the repository and run `git worktree add ../portfolio-legacy legacy-portfolio`. Do not reset or overwrite the terminal checkout to inspect the legacy design. The original working checkout's unrelated personal-data edit is intentionally excluded from this promotion.

The content in `src/content.ts` is a snapshot of the repository's working-tree `src/data/personal.ts`, `src/data/projects.ts`, `src/data/skills.ts`, and the about copy and selected identifiers from `src/components/Portfolio.tsx`, taken on October 13, 2026. The Mac Digital, Drop It, Amountly order and existing links are preserved. No provider status or content claims were refreshed. Reviewed operational screenshots were omitted from this text-focused terminal because they contain business data and patient-shaped records. The cyan lightning bolt is a native pixel-style SVG used in the welcome area and favicon.

## Local development

Uses TypeScript and the native Sites Worker ESM contract, with no runtime npm dependencies. From the repository root (use Node 24 or newer for the local SQLite adapter):

```sh
npm ci
npm run db:generate # after schema changes
npm run typecheck
npm run build
npm test
npm run dev
```

Open `http://127.0.0.1:4173` in the Codex in-app browser. To rebuild elsewhere, install the locked development dependency first. Authored HTML, CSS, and SVG live in `web/`. The build compiles TypeScript into `build/`, then embeds the public assets and the answer handler into the single `dist/server/index.js` Worker with its matching hosting manifest. Build validation imports the resulting ESM artifact and checks `default.fetch`. The development adapter binds only to loopback and is excluded from the Worker artifact. It can read an explicitly selected existing local env file via `PORTFOLIO_OPENAI_ENV_FILE` without copying that file. Hosted configuration uses native Sites secrets. Deploy only `dist` through the Sites source helper and native publishing operation appropriate to the current audience. Preserve audience settings unless the user requests a change. Source preparation uses a sanitized publication checkout separate from the portfolio Git repository, so the helper's commit/push cannot include unrelated portfolio edits or target GitHub. Do not include `.gitignore`, local `.env*` files, credentials, repository metadata, or the output archive in source.

## Behavior

`/help`, `/about` (`/home`), `/projects`, `/project <slug or full name>`, `/work`, `/skills`, `/contact`, `/history`, `/clear`. Help documents the optional bare-word aliases. Type `/` to open a command picker with descriptions; up/down select a row, Tab inserts it, and Enter runs it. Choosing `/project` first opens the project picker. Every existing project identifier and title is supported. Clicking a picker row inserts it for review; welcome and output shortcuts run their stated commands directly.

The prompt grows to six visible rows. Shift+Enter, Alt+Enter, or backslash+Enter adds a newline; Enter submits a question or one allowlisted command, with command whitespace normalized. With the picker closed, up/down recall prompts at the first/last logical line and restore the current draft. Ctrl+R or `/history` opens an inline, session-only history search; arrows select a match and Enter/Tab restores it for review. Escape cancels the search and preserves the draft. `?` in an empty prompt toggles inline shortcuts; Escape closes panels and double Escape clears the draft. Ctrl+S stashes/restores one in-memory draft with cursor selection; Ctrl+U deletes to the current line start; Ctrl+C clears an unselected prompt without changing normal copy behavior. The clickable history, help, and stash controls support touch access.

Normal prose is sent to the same-origin `/api/answer` endpoint. Slash commands and exact documented bare-word aliases continue to resolve locally. Input is limited to 1200 characters; displayed responses and recalled prompts are limited to 40 each. All input/content uses DOM text nodes. Navigable destinations are restricted to existing product hosts, GitHub, and simple email addresses. External links open in a separate tab with `noopener noreferrer`. Status announcements are concise; output remains ordinary readable document content. The prompt is sticky while reading long output and scroll changes happen only upon explicit submission. The terminal block cursor follows the insertion point, wrapped lines, and textarea scrolling; native caret/selection behavior remains available for selection, composition, and forced colors. Its blink stops under reduced-motion preferences.

## Grounded, conversational portfolio answers

OpenAI Responses uses `gpt-6-luna` at low reasoning effort with the existing server-only Site secret. The guide answers harmless everyday questions, math, greetings, definitions, and writing requests, and gently invites visitors to explore Iver’s work. Short questions receive brief replies; explicit essay requests can receive several paragraphs. General statements can have no catalog references, but factual claims about Iver or a portfolio project always require exact catalog fact IDs. A separate stateless review checks safety, correctness, completeness, and that portfolio claims follow from the selected canonical evidence, with correct attribution to each project. Cross-paragraph summaries can rely on facts established earlier in the same answer; unrelated facts cannot establish a feature or stack for a different project. Deterministic number/technology checks still use each statement’s own references. Source-free statements cannot bypass portfolio grounding. Trusted owner/assistant-role metadata supports attribution and ordinary conversation. Missing personal/project details and fabrication requests receive fixed truthful replies.

One rejected draft may be corrected using the reviewer’s feedback, then checked independently again. Only a complete safe positive review permits natural text to reach the browser. Provider refusals, content-filter results, and unsafe reviewer verdicts produce a fixed safe reply rather than a service error. Provider or network failures are not retried. Failed portfolio reviews retain a catalog-derived fallback; failed general reviews do not display the unapproved draft. Semantic review and safety checks reduce risk but are not a proof of every claim or a guarantee against every harmful prompt.

Documented technology lists and exact feature questions still provide deterministic required evidence. An explicit all-three shared-stack follow-up retains the earlier three-project group after a narrower follow-up and requires every documented stack. The model may phrase those answers naturally, but omitting required evidence returns the complete source-derived answer. This preserves the Python regression fix and unambiguous follow-ups. The curated portfolio snapshot is the sole evidence for claims about Iver and his projects. Stable general knowledge is permitted for ordinary questions. Neither model has browsing, tools, shell, filesystem access, financial integrations, or private personal records. The last four questions, bounded prior replies, and validated source IDs resolve conversational context only. Prior replies and alleged user facts are never portfolio evidence. Previous displayed errors are remembered so the guide can acknowledge a failed reply without inventing its cause. Context is trimmed by encoded byte size before submission, within the existing 16 KiB request limit. Alleged facts in user text are not evidence. Portfolio claims are not independently verified current status reports.

The terminal displays a cyan animated glyph while the answer is prepared and checked. The answer display contains only the conversational text; source links and supporting-excerpt controls are omitted. Catalog evidence remains part of validation and follow-up context. After the server completes grounding, verified text is progressively revealed for at most 2.4 seconds, with an animated terminal cursor. This is a presentation animation, not raw provider-token streaming: unreviewed text is never shown. Reduced-motion preferences use a static glyph and immediate answer display. Status announcements are limited to state changes. Escape, `/clear`, or the stop control cancels both waiting and reveal; drafts are preserved. `/clear` also clears conversational context.

Runtime `OPENAI_API_KEY` stays a native Site secret. `OPENAI_MODEL` is allowlisted to `gpt-6-luna`; `PORTFOLIO_ORIGIN` is the exact original Site origin. Optional `PORTFOLIO_ADDITIONAL_ORIGINS` is a JSON array of at most four exact HTTPS origins for verified custom domains; set it in Sites runtime configuration when binding a new domain. Malformed configuration fails closed, and request Host/forwarded headers never extend the allowlist. Hosted AI requests accept anonymous same-origin JSON. An opaque HttpOnly/Secure/SameSite browser cookie identifies a usage bucket; it is not authentication, and account headers grant no privileges. Request bodies are bounded to 16 KiB, provider responses to 64 KiB. Request fields, context, identifiers, string lengths and provider status are validated. No prompts, answers, provider errors, headers, or tokens are logged. Calls use `store: false`, strict schemas, fixed output budgets of 4096 and 1536 tokens, a shared 60-second server timeout, and no provider/network retry. There are normally two provider calls; a single optional draft correction can bring this to at most four. Natural reply text is limited to 8000 characters, each draft statement to 1400 characters, and catalog evidence to 64 verified references. Long evidence can produce a bounded excerpt fallback without invalidating a valid essay. One active logical question per visitor, twelve per minute and sixty per day are enforced per Worker isolate across writing and review. These in-memory controls are supplementary. A native D1 binding also atomically admits at most 6 paid questions per browser bucket per minute, 20 per bucket per UTC day and 100 site-wide per UTC day across Worker instances. Clearing cookies cannot reset the shared site-wide cap. A browser bucket is not proof of one person; this is a bounded public endpoint, not bot-proof identity. Reservations are counted conservatively even if a provider request later fails. Missing, failed or malformed budget storage fails closed before any provider call. Only random reservation IDs, hashed browser buckets and UTC day/minute counters are stored, with old rows removed after the following UTC day. No questions, answers, account identities or IPs are stored in D1. Public Site audience remains controlled by native Sites access settings.

Focused tests cover input and identity/origin validation, complete review coverage, missing/duplicate verdicts, fabricated figures and stacks, malicious drafts, reviewer outages, exact-excerpt fallback, required technology coverage, cancellation, logical-request rate limits, commands, editing, cursor behavior, and public Worker routes. Real question evaluations and in-app browser QA cover ordinary questions, comparisons, follow-ups, false premises, unknown facts, loading, cancellation, animation, reduced motion and narrow screens. Historical evaluation files describe their tested version; the natural-answer evaluation records the newer two-pass flow.

## Anonymous questions

`db/schema.ts` owns the schema; generate schema-only migrations with `npm run db:generate`. The build copies their SQL and Drizzle metadata to `dist/.openai/drizzle` for native Sites migration before Worker upload. The hosted `DB` binding enforces admission with a single conditional INSERT inside a D1 batch; a denied visitor does not spend another visitor's quota. No runtime table creation or manual hosted SQL is used. Migration generation uses pinned development-only Drizzle tools, with patched esbuild; the deployed Worker still has no runtime npm dependencies.

The previous authenticated-only security report remains historical. The anonymous release intentionally replaces the sign-in boundary with explicit public admission, same-origin/schema checks and shared usage caps. The existing grounding, refusal, model, output-token and call-count limits remain in place. Regression tests execute the generated schema and actual admission SQL in SQLite, including parallel admissions, separate handler instances, fresh cookies, forged account headers, daily rollover, denied-request accounting and storage outages.
